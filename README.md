

# Keitaro Wrapper

Веб-приложение для работы с кампаниями и потоками Keitaro через Admin API v1. Приложение хранит локальные черновики изменений офферов, позволяет пересчитывать доли, архивировать и восстанавливать офферы, синхронизировать состояние с Keitaro и отправлять изменения обратно.

**Стек:** Python · FastAPI · SQLAlchemy 2 · PostgreSQL · Alembic · httpx · HTML/CSS/JavaScript.

> **Важно:** запись в Keitaro по умолчанию отключена. Параметр `KEITARO_WRITE_ENABLED=false` блокирует создание кампаний и публикацию изменений. Не включайте запись, пока не проверили интеграцию на тестовом аккаунте или кампании.

## Возможности

- Создание кампании в Keitaro с GEO-потоком и default-потоком с выбранным оффером.
- Подключение существующей кампании Keitaro по её ID.
- Загрузка потоков и офферов из Keitaro в локальную базу.
- Локальное редактирование состава офферов без немедленной записи в Keitaro.
- Изменение и закрепление долей офферов.
- Удаление оффера в черновике, архивирование и восстановление (**Bring back**).
- Отмена неопубликованных изменений (**Cancel**).
- Публикация изменений одного потока или всех потоков кампании.
- Журнал операций с офферами.

## Как устроена работа с данными

Для каждой привязки оффера к потоку хранятся два состояния:

- `published_*` — последнее известное опубликованное состояние в Keitaro;
- `draft_*` — локальное состояние, которое подготовил пользователь.

Поток считается изменённым (**dirty**), если черновик отличается от опубликованного состояния. Флаг dirty вычисляется из данных и отдельно в БД не хранится.

### Распределение долей

- Сумма долей активных офферов должна составлять ровно **100%**.
- Закреплённые офферы сохраняют заданные доли.
- Остаток распределяется поровну между незакреплёнными офферами.
- Остаток от целочисленного деления распределяется по порядку: например, 75% на двоих превращаются в 38% и 37%.
- Нельзя удалить последний активный оффер.
- При невозможности корректно распределить доли операция отклоняется, изменения не сохраняются.

При удалении оффера его закрепление снимается, а доля становится 0%. При восстановлении оффер возвращается незакреплённым. **Cancel** возвращает черновые значения к опубликованным, но не сбрасывает отдельную настройку закрепления.

### Синхронизация

При открытии кампании приложение по умолчанию запрашивает актуальные данные Keitaro (`GET /api/campaigns/{id}?refresh=true`). Также обновить данные можно кнопкой **Fetch Streams**.

- Если оффер удалили непосредственно в Keitaro, локальная привязка сохраняется в архиве.
- Если поток исчез из Keitaro, он помечается как удалённый, а не удаляется из локальной БД.
- Неопубликованные локальные черновики не перезаписываются данными синхронизации.
- Потоки без офферов отображаются, но их внутренние настройки (например, redirect и filters) в интерфейсе не редактируются.

### Публикация

Публикация выполняется отдельно для каждого потока одним запросом `PUT /streams/{id}`.

- Локальное опубликованное состояние обновляется только после успешного ответа Keitaro.
- Ошибка одного потока не мешает обработке остальных потоков кампании.
- Результат возвращается отдельно для каждого потока: `published`, `error` или `unchanged`.
- Если Keitaro принял изменение, но локальная запись не сохранилась, выполните синхронизацию (**Fetch Streams**).

## Требования

- Python **3.10+**.
- PostgreSQL.
- Доступ к Keitaro Admin API v1 и действующий API-ключ — для чтения и синхронизации.
- Git — если проект клонируется из репозитория.

Docker-конфигурация в проект не включена.

## Установка и запуск (Windows / PowerShell)

Клонируйте репозиторий и перейдите в его папку:

```powershell
git clone https://github.com/blazzard7/keitaro_wrapper.git
cd keitaro_wrapper
```

Создайте виртуальное окружение и установите зависимости:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Создайте в PostgreSQL базу данных, например `keitaro_wrapper`:

```sql
CREATE DATABASE keitaro_wrapper;
```

Создайте файл конфигурации:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите параметры подключения к своей БД и Keitaro:

```dotenv
DATABASE_URL=postgresql+psycopg://postgres:YOUR_PASSWORD@localhost:5432/keitaro_wrapper
KEITARO_BASE_URL=https://YOUR-KEITARO-HOST/admin_api/v1
KEITARO_API_KEY=YOUR_API_KEY
KEITARO_WRITE_ENABLED=false
```

Замените значения-заглушки на свои. Не публикуйте файл `.env` и не отправляйте API-ключ в Git.

Примените миграции и запустите приложение:

```powershell
alembic upgrade head
uvicorn app.main:app --reload
```

Откройте в браузере:

- Интерфейс: http://127.0.0.1:8000
- Swagger / OpenAPI: http://127.0.0.1:8000/docs
- OpenAPI JSON: http://127.0.0.1:8000/openapi.json

Для остановки сервера нажмите `Ctrl+C`.

## Настройки окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | Строка подключения к PostgreSQL через psycopg 3 |
| `KEITARO_BASE_URL` | Базовый URL Keitaro Admin API v1 |
| `KEITARO_API_KEY` | API-ключ для заголовка `Api-Key` |
| `KEITARO_WRITE_ENABLED` | Разрешение операций записи; по умолчанию `false` |

При `KEITARO_WRITE_ENABLED=false` методы записи в Keitaro блокируются приложением с ответом **403**. Чтение данных Keitaro всё равно требует доступного API и корректного ключа.

## Работа через веб-интерфейс

### Подключить существующую кампанию

1. Откройте раздел **Кампании**.
2. Введите ID кампании в поле **ID кампании в Keitaro**.
3. Нажмите **Подключить**.
4. Выберите кампанию из списка. При открытии приложение синхронизирует её потоки.

### Изменить офферы

В карточке потока с офферами доступны действия:

- **Добавить оффер** — найти оффер по ID или названию и добавить в черновик.
- **Закрепить** — зафиксировать долю оффера; доли остальных незакреплённых офферов будут пересчитаны.
- **Пересчитать** — повторно распределить доли.
- **✕** — убрать оффер из черновика и перенести его в архив.
- **Bring back** — восстановить архивный оффер.
- **Cancel** — отменить неопубликованные изменения потока.
- **Push to Keitaro** — опубликовать изменения текущего потока.
- **Push all** — опубликовать изменения всех потоков кампании.

Изменения состава и долей сначала сохраняются локально. До нажатия Push они не отправляются в Keitaro.

### Создать новую кампанию

В разделе **Новая кампания** укажите название, двухбуквенный код GEO, оффер, домен, группу и источник трафика. При создании приложение формирует кампанию, GEO-поток с HTTP-редиректом и default-поток с выбранным оффером.

Создание кампании — операция записи в Keitaro. При выключенном `KEITARO_WRITE_ENABLED` она не выполнится.

## HTTP API

Полная интерактивная документация доступна по адресу `/docs`. Основные маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| `GET` | `/api/campaigns` | Список локальных кампаний |
| `POST` | `/api/campaigns` | Создать кампанию в Keitaro |
| `POST` | `/api/campaigns/import` | Подключить существующую кампанию |
| `GET` | `/api/campaigns/{id}` | Получить кампанию и, по умолчанию, синхронизировать её |
| `POST` | `/api/campaigns/{id}/publish` | Опубликовать изменения всех потоков |
| `GET` | `/api/keitaro/domains` | Получить домены |
| `GET` | `/api/keitaro/groups` | Получить группы |
| `GET` | `/api/keitaro/traffic-sources` | Получить источники трафика |
| `GET` | `/api/keitaro/offers?q=` | Поиск офферов по ID или названию |
| `POST` | `/api/streams/{id}/offers` | Добавить оффер в черновик |
| `DELETE` | `/api/streams/{id}/offers/{offer_id}` | Удалить оффер из черновика |
| `POST` | `/api/streams/{id}/offers/{offer_id}/restore` | Восстановить оффер |
| `PUT` | `/api/streams/{id}/offers/{offer_id}/pin` | Закрепить или открепить долю |
| `POST` | `/api/streams/{id}/rebalance` | Пересчитать доли |
| `POST` | `/api/streams/{id}/cancel` | Отменить черновые изменения |
| `POST` | `/api/streams/{id}/publish` | Опубликовать один поток |
| `GET` | `/api/streams/{id}/history` | История изменений офферов |

## Тестирование

Запуск тестов:

```powershell
pytest -v
```

Тесты проверяют бизнес-логику долей и черновиков, API-маршруты, синхронизацию и обработку публикации. Для изоляции от внешнего сервиса используются тестовая SQLite-БД и подменяемый HTTP-клиент Keitaro; тестовый прогон не должен изменять реальные кампании.

Последний зафиксированный локальный прогон: **75 тестов пройдены**.

## Ограничения и статус интеграции

Проект реализует клиент Keitaro Admin API v1, но совместимость отдельных операций необходимо подтвердить на целевом экземпляре Keitaro. В частности, перед включением записи следует проверить:

- создание потоков через `POST /streams` и используемые значения `schema`;
- обновление офферов через `PUT /streams/{id}` с payload, содержащим `offers`;
- фактическую структуру ответа `GET /campaigns/{id}/streams`;
- дополнительные обязательные поля кампании, если они настроены в конкретном экземпляре Keitaro.

В текущей среде полноценная проверка интеграции ограничена ответом **HTTP 403** со стороны Keitaro. Поэтому создание кампаний и Push не следует считать подтверждёнными на рабочем экземпляре. До успешной проверки оставляйте `KEITARO_WRITE_ENABLED=false`.

## Безопасность

В приложении не реализована пользовательская аутентификация. Запускайте его только локально или в доверенной внутренней сети. Не публикуйте сервис в открытый интернет без добавления аутентификации и соответствующих сетевых ограничений. Храните API-ключ и пароль БД только в локальном `.env`, который не должен попадать в репозиторий.
